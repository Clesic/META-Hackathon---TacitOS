# User experience and copy

## Design direction

A calm, focused workbench. The main object is a task being handed over, not a score for an employee. Use three clear stages: Rehearse, Capture, Retest. Keep the current case and source evidence visible. Avoid a giant readiness percentage with no denominator.

## Screen 1: Start a rehearsal

Headline: “Could the team handle this without calling the expert?”

Workflow: “Purchasing exceptions — synthetic demo.”

Explain: “Practice only. No orders are sent. We will record decisions made inside this rehearsal.”

Primary action: “Start Monday.” Show which handbook version and approved guidance are available. Offer a reset only with a clear description of what local session data will be cleared.

## Screen 2: Successor task

Show task, facts, documents and allowed actions. Actions: inspect evidence, accept, reject, request evidence, escalate. A help action says “I need the expert.” Before finalizing, the successor supplies a short reason and cited evidence. Do not force the system to pretend an undocumented exception is known.

Blockage copy: “This task needs a condition the available guidance does not explain.” If the issue is permissions, say so instead.

## Screen 3: Expert capture

Show the failed attempt and the focused question together. Let the expert answer in text, edit the question's premise, or say “I don't know.” The expert can flag that the scenario is unrealistic.

Draft card view separates action, conditions, exceptions, missing information and supporting quote. Buttons: “Approve this version,” “Edit,” “Reject.” Do not preselect approval.

## Screen 4: Fresh case

Copy: “New order. Same knowledge boundary. Expert unavailable during this rehearsal.”

Make the approved guidance available, not the hidden answer. Do not label the correct action in the screen title. The actor's chosen action is evaluated only after submission.

## Screen 5: Evidence of transfer

Show counts: tasks independently completed / tested tasks; incorrect actions / submitted decisions; direct expert contacts; safe escalations; unresolved dependencies. Separate before and after cohorts and explain that cases differ.

Example wording before data exists: “No transfer tests completed yet.” After a real run, derive every value from records. A single pass should read “Demonstrated on this case,” not “Role secured.”

## Accessibility and failure states

All actions are keyboard-accessible, focus is visible, color is not the only status indicator, and status text is readable by screen readers. Show loading states and preserve entered text on API failures. Errors say what failed and how to retry. The simulated expert and simulated successor are visibly labelled wherever used.

# Data handling and control boundaries

The prepared pack contains fictional company data only. The first demo should preserve that scope. This is a technical plan, not a legal compliance determination.

## Capture

Record actions inside the rehearsal and explicitly submitted expert answers. No general desktop monitoring, private messages, keystroke capture or employee personality scoring. Explain recording and allow the participant to stop. If voice is added, document audio storage, transcription destinations and deletion behavior before use.

## Provider and credentials

Keys stay server-side in a private environment file and never enter the public repository, browser bundle, prompts or video. Provider use, retention and training terms must be checked for the actual account mode before any real data is used. No provider tier is declared safe for personal data by this pack.

Do not copy the shared parent `.env` into the new folder. The example file deliberately contains an empty key. A later implementation may read an explicitly configured private path with the user's existing authorization; do not expose that file's contents.

## Expert control

The expert reviews the precise guidance version. Rejection and revocation are first-class actions. Preserve limits and uncertainty. Approval is not proof of correctness or evidence of consent for every possible later use.

## Access and publication

Expert-only and evaluator-only fixtures are hidden from learner contexts, even though synthetic fixtures can be published for reproducibility. Runtime logs, participant data, recordings and databases remain private by default. Publish only intentionally curated synthetic evidence after inspection.

## Retention

Choose an explicit retention period before a real pilot. Define deletion across answers, cards, embeddings if added, logs, exports and backups. The demo cannot claim complete production deletion or secure multi-tenant isolation.

## Scope of operation

All accept, reject and routing actions affect a simulated order only. Any future real-world action needs separate authorization and appropriate business controls. A private or sovereign deployment is future scope and would require checking every data path, not merely changing the model endpoint.
